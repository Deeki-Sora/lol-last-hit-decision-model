# 工作台详细使用指南

## 1. 准备环境

下载或克隆完整仓库，进入仓库根目录。需要 Python 3.11+ 和 FFmpeg/ffprobe，安装方法见 README。先运行：

```sh
python --version
ffmpeg -version
ffprobe -version
python main.py --help
```

基础流程不需要 pip 安装包。颜色候选、HTTPS 证书包、矩阵求解器和浏览器自动化测试均为可选项。工作台只启动本地服务，不要求登录 AI 账号或连接某个插件。

## 2. 选择录像与时间

将录像放入仓库空白 input_videos/ 文件夹，或准备自己的目录。常见 mp4、mkv、webm、mov、avi、m4v 可选，是否能解码由 FFmpeg 决定。

```sh
python main.py
```

启动后按顺序输入：

1. 录像文件夹。回车使用 input_videos；输入完整路径选择自己的目录；输入 choose 打开系统文件夹选择器。
2. 文件编号。多个文件使用逗号，例如 `1,3`，每个文件分别建立工作区。
3. 采样间隔。填写 0.1–0.5 秒，回车为 0.3 秒。
4. 可选距离标尺。`189=350` 表示 189 像素约为 350 游戏单位；回车只记录像素。
5. 是否使用首波名册模板。确认是第一波普通小兵时输入 y；其他窗口回车，先只建双方英雄，再按画面加入实际小兵。
6. 逐视频填写开始、结束时间。可填秒数、MM:SS 或 HH:MM:SS，均为源视频时间，不是画面中的游戏时钟。

脚本在 runs/ 下生成新目录和逐文件 clip_XX，不覆盖源视频。多段完成采样后依次打开标注页面；结束前一个本地服务（终端 Ctrl+C）会进入下一个。之后可随时单独重开指定工作区。

等价命令：

```sh
python main.py sample --video input_videos/match.mp4 --start 1:00 --end 1:30 --step 0.3 --scale 189=350 --output runs/session/clip_01 --review
```

输出目录必须尚不存在。如果需要首波模板，加 --first-wave-template；如需颜色候选，先安装 requirements-vision.txt，再加 --proposals。采样使用实际视频帧，变帧率视频或低帧率视频的实际间隔可能略有偏差，表内 source_time_s 是依据。

## 3. 认识页面

左侧为截图和切帧工具；右侧为当前单位和动作输入。下方为标尺、英雄资料、策略以及独立的可选推演面板。主页面按钮对应：

顶部 Language / 语言在中文和 English 之间切换，不改变数据 ID 或翻译用户备注。命令行参数和表格字段保持英文。

| 控件 | 操作 |
| --- | --- |
| 上一帧、下一帧、进度条 | 按实际采样帧切换；输入框外可用左右方向键 |
| 当前单位 | 选择蓝方/红方英雄或已编号小兵；身份必须自己核对 |
| 当前单位血条中心 | 直接点击完整血条中心 |
| 拖框选完整血条 | 从完整血条一角拖到另一角，脚本取框的中心 |
| 固定地图纹理原点 | 在每帧点击同一个可追踪纹理点，用于扣除镜头平移 |
| 清除此单位坐标 | 本帧位置留空，不用错误位置凑完整距离 |
| 记录此帧动作 | 将当前动作表单记录到内存；还需保存到磁盘 |
| 保存 | 保存名册、标注、标尺与预输入 |
| 保存并导出评估包 | 保存并重算所有表格，生成独立 ZIP |

切换单位或帧时会记录当前表单，但浏览器关闭前仍应点击保存。页面没有后台自动补完单位身份或动作的功能。

## 4. 建立双方小兵名册

展开“单位列表与新增单位”，选择阵营、兵种、波次后点击加入。ID 留空时自动生成 `red_melee_w2_1`、`blue_siege_w3_1` 等永久唯一编号；序号没有 1–6 上限，阵亡编号不复用。波次不确定可填 0 并在备注说明。新增单位从当前帧开始参与记录；需要更早生效可由 AI 或人工修改 project.json 的 first_seen_s。

兵种可选近战、远程、炮车、超级兵、待确认小兵和召唤物。颜色候选不自动识别炮车；可人工确定兵种，也可导入 AI 标注。已经加入的单位在后续帧继续沿用同一 ID，不因位置移动重新编号。错误的模板单位需在 project.json 名册中修正，并同步修正其标注，不要伪装成已经阵亡。

展开逐项距离对象选择，或点击“选取名册内当前全部未确认阵亡的小兵”。选择不限数量，沿用到后续帧直到重新选择。新增兵波加入名册后，应再次确认距离对象；死亡单位自动剔除。默认只记录双方英雄间以及英雄到对方选定小兵的距离，没有己方小兵距离或小兵两两距离。

单方超过六只且未明确选择时，导出会要求先选择，避免自动猜测多波身份；并非六只上限。只想测英雄距离可点击“只测英雄之间”。输入 `[]` 也表示此模式。

## 5. 标注坐标、动作和相位

按同一原图像素口径定位完整血条中心；不要用剩余彩色血量段的中心。彩色候选为橙色虚线框，只提供查找提示，不能直接证明完整血条或阵营。

动作建议统一采用 attack、技能标识、move、wait、death 等；相位可用 windup、committed、impact、recovery，必要时写备注。目标选择具体单位 ID；动作开始/结束填写源视频秒数。一个动作跨几张截图持续出现时，开始时间保持相同，不能按截图数增加攻击次数。

生命值按数值或比例记录均可，但必须在备注说明口径；不能把百分比直接作为推演用的实际 HP。确认阵亡时设置 alive=false 或动作 death，该帧起不再记录该单位距离。看不清设置未知，不等于死亡。错误死亡标注需要回到原帧更正，否则后续会一直排除。

同帧间距只需双方中心。跨帧位移需要每帧同一地图纹理原点；没有原点时位移留空。换缩放后应在 annotations.json 的帧中设置不同 scale_id，避免跨尺度比较。标尺只是估计，不能直接证明攻击射程的地面判定。

## 6. 填入英雄和策略资料

在“评估预输入”的可视化选择区加载录像补丁，选择双方中英文英雄名称、主副系符文及属性碎片，点击保存并锁定。切到对应截图，选择等级、技能加点、装备槽及数量，确认背包完整性，再点击“将此状态记录于当前帧”。更晚的装备快照不影响此前事件。具体步骤见 [配置选择指南](loadout_selection.md)。

内置选择器独立可用。候选 ARAMonly 入口通过 Shareable URL 导入名称/ID，保留工作台原英雄选择；其 Download 图片不是结构化导入文件。网站缺少英雄、停用或数据不匹配时，可以继续使用内置目录。外部网页展示的数值不参与计算。

自动携带的基础属性、被动、技能、符文和装备描述属于静态引用，不会自动完成有效攻速、特殊射程、冷却修正或触发机制。可视化配置的 verified_effective_state 保持 false。高级 JSON 接口仍可保存经人工/AI 核验的机制参数；启用可选推演时须补齐任务规则。

一般对线策略可选，以纯文字写适用条件、收益/成本、何时失效和来源链接。不要把策略文字当成已经观察到的动作。两者保存到 project.json，导出时一并提供给评估者。

## 7. 表格、AI 辅助与重新导入

点击导出后，tables/ 中包含 events.csv、distances.csv、actions.csv、deaths.csv、coverage.json。事件表按帧和单位记录；动作表按单位及明确动作开始时间去重。坐标未知不会变成零距离。

人工编辑 events.csv 后运行：

```sh
python main.py import-table runs/session/clip_01 edited_events.csv
```

保留 frame_id、unit_id；不要新建重复行。改 x_px、y_px、动作或相位后导回，脚本重新计算派生距离，手写距离列不会覆盖计算。默认 UTF-8 BOM；明确使用其他编码时可加 --encoding。已经写进源文件的字面问号无法靠转码恢复。

AI 可按 [JSON 格式](workflow.md#4-ai工程接口) 输出 annotations.json，使用页面导入或直接写入工作区。名册已有的 ID 才能引用，AI 坐标保持 reviewed=false，人工核对后再确认。先备份原标注，避免导入覆盖。

## 8. 可选机制观察与博弈

普通评估可以跳过这一节。需要短时反事实时，切到决策帧并生成任务，不预置任何英雄数据；概率观察表也不会自动认出录像中的机制。按 [完整推演指南](short_horizon.md) 核验参数、输入候选、记录独立机会和适用条件，再选择 compare、zero_sum 或 general_sum。

compare 无需下载数值包；其他模式显示下载链接并由用户决定安装。先观察有效终点和双方成本，再选择收益权重。升级、符文/被动造成未支持的属性变化或未知转火时，更新状态并另开任务。不能把短时放弃一刀当作对局失败。

## 9. 导出给其他人或其他 AI

最后重新点击“保存并导出评估包”。assessment_bundle.zip 包括截图、原始标注、表格、参数、策略、双语框架、评估请求，以及存在时的机制观察和推演结果。接收方不需要访问你的源项目目录；没有包含的未知数据仍需说明。

使用评估请求分别评价双方，单片段与多片段采用一致规则。推演输出是可复核的局部分支证据，不直接等于总分或段位。包中不自动包含原始完整录像；需要让他人复核未采样细节时，另外提供有权分享的视频。

## 10. 关闭、恢复与常见错误

```sh
python main.py review runs/session/clip_01
python main.py export runs/session/clip_01
```

关闭浏览器不会删除工作区；关闭终端会停止本地服务，重开即可恢复已保存内容。不同运行会有新的本地会话地址，使用终端打印的当前地址。

- FFmpeg/ffprobe 未找到：安装后重开终端，检查 PATH。
- 没有视频：确认文件夹路径和后缀，交互选择是文件编号，不是文件名。
- 输出目录已存在：改用新输出目录；已有工作区用 review。
- 距离未知：检查两个中心、单位身份、死亡状态和距离对象选择。
- 位移未知：检查跨帧纹理原点与 scale_id；同帧距离不受这个限制。
- 未核验机制/参数报错：补齐任务 JSON 或缩短有效窗口，不要直接将 verified 改为 true。
- 概率适用条件失效：按实际距离、移动、等级等重新分组观察，或使用确定机制/隐藏状态情景。
- 有效窗口过短或为零：先处理对应升级、仇恨或属性更新，再从新初态规划；不以旧窗口求解作长期结论。
