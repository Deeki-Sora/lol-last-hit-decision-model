# 英雄、符文与装备选择

## 1. 数据流与独立性

工作台的可视化选择界面将名称转换为稳定 ID，保存结构化配置。后台再从锁定补丁的目录读取对应资料。选择器提供名称和身份；其网页展示的伤害、回血、攻速或冷却数值不进入计算。

| 输入 | 生效范围 | 数据位置 |
| --- | --- | --- |
| 录像补丁、双方英雄、符文、属性碎片 | 整场对局的固定配置 | configuration.match_setup |
| 等级、Q/W/E/R 加点、完整或部分背包 | 从指定视频时刻开始，直到下一条状态快照 | configuration.snapshots |
| 血蓝、攻击相位、目标与动作 | 对应观测事件 | annotations.json / 事件表 |
| 有效战斗规则、临时层数与复杂效果 | 经核验的短时任务 | 推演任务的 units / stochastic |

内置选择器是主入口。外部网站为可选入口，网站停用不会影响已有目录缓存、选择配置、采样、标注和表格导出。首次获取尚未缓存的补丁资料仍需要数据服务可用。没有找到数据时不以另一版本代替。

## 2. 中英文界面

标注页面顶部 Language / 语言可切换中文、English，浏览器记住选择。名称随界面语言显示，同时保留英文名和 ID。切换语言不会翻译用户写入的策略、备注或 JSON，也不会改变选中单位或配置 ID。命令行参数名与数据字段保持英文。

首次打开默认中文。宽屏按蓝方、红方并列显示，对应的英雄、符文、等级、技能加点和装备区域对齐；窄屏改为上下排列。两方均可独立填写，不要求先完成某一方。固定配置保存及状态快照记录均同时包含蓝红双方。

## 3. 加载录像版本并选择双方英雄

1. 运行 main.py，完成采样后打开标注页面，找到“英雄、符文与时点装备选择”。
2. 输入录像补丁，如 `26.6`，或精确 Data Dragon 版本，如 `16.6.1`，点击“加载此版本目录”。2026 年公开补丁 `26.N` 对应 Data Dragon 的 `16.N.build`；工作台在版本列表中选择该补丁的最高可用 build，并显示最终锁定值。可以直接输入精确版本固定同一次快照。
3. 在蓝、红两方分别输入中文名称、英文名称、称号或 ID，从列表选择。名称匹配不区分英文大小写；无法解析的俗称需要选择列表里的名称。没有预设任何对局或英雄。
4. 选中后读取英雄基础属性、被动和 Q/W/E/R 原始资料。未选英雄保留未知，不会从外部配置网站猜测英雄。

目录数据来自 [Riot Data Dragon](https://developer.riotgames.com/docs/lol#data-dragon)。属性碎片名称和槽位来自同补丁的 [CommunityDragon](https://www.communitydragon.org/)；该数据项目在 2026 年仍有更新。工作台不包含旧符文模拟器代码，亦不下载运行外部程序。文件来源、HTTP Last-Modified、抓取时间与 SHA-256 随目录保存。源码更新时间不能替代数据补丁核验。

如果中文资料暂不可用，会保留同补丁的英文资料并显示警告。属性碎片目录不可用时保持未知，不使用其他年份的碎片选项。

## 4. 选择固定符文页

依次选择主系、基石、三行主系符文、副系、两个副系符文及三项属性碎片。未知槽位可以暂留空；默认不会替玩家选一套主流符文。

点击“保存并锁定英雄和符文”。后台检查符文是否存在于该补丁、主副系是否不同、主系槽位和副系行是否正确。两个副系符文必须来自不同的行。

固定配置锁定后，切帧和修改背包不会改变符文。纠正录入错误时，勾选“编辑 / 纠正对局固定配置”。更换英雄或补丁时需要清空原状态快照，以避免将另一英雄或另一版本的状态沿用到本对局。

## 5. 按时间记录等级、加点和装备

1. 切到需要建立状态的截图，使用源视频时间，不使用画面里的游戏时钟。
2. 点击“读取当前帧对应状态”，读取该时刻之前最近的快照。此前没有快照时，等级、加点和背包完整性均为未知。
3. 选择双方等级、技能加点，在六个装备槽中输入名称或 ID；数量填写该槽的堆叠数量，饰品单独使用第七槽。
4. 看清完整背包后才勾选“已确认此时完整背包”。未勾选时，选出的装备表示已知部分，空槽不能证明没有装备。
5. 点击“将此状态记录于当前帧”。同一时间再次记录会替换该时刻快照；更晚的时间创建新快照。可以在快照列表回看或删除误录。

切帧后表单保留正在编辑的内容，并显示时间提示；不会悄悄覆盖未提交的输入。记录前应确认这些值适用于当前帧。网站的装备规划也不能证明这些装备已经购入。

读取时只使用 `snapshot.source_time_s <= event.source_time_s` 的最近快照。较晚购买的装备不会用于更早的事件。系统记录观察到的背包，不模拟购买、售卖、金币支付或自动推定回城。

## 6. 候选外部入口：ARAMonly

[ARAMonly Runes Builder](https://www.aramonly.com/lol-runes-builder/)提供可视化符文与装备选择。其 Download 导出 PNG 快照，工作台的自动入口使用 **Shareable URL**，无需从图片识别名称。该网站是外部服务，不属于本仓库代码或 MIT 授权范围。

1. 先在工作台加载录像的补丁、选择并保存双方英雄。
2. 展开“候选：ARAMonly 符文 / 装备分享链接”，打开网站。可以不选择英雄，也可以忽略网站中已有的英雄。
3. 在网站选择符文、装备，复制 Shareable URL，粘贴到工作台并选择蓝方或红方。
4. 点击“解析并预览”。检查网站声明的补丁、本地锁定补丁、解析出的名称、未能匹配的符文和无效装备。
5. “将符文应用到此方固定配置”仅更换这一方的符文，不改变双方英雄。无法匹配的符文会阻止应用，不会自动换成另一个符文。
6. “将装备填入此方状态表单”仅填入已识别的装备；不会自动记成已购买。核对数量、饰品、完整性与时间，再记录状态快照。网站未表示装备数量时以每槽 1 件填入表单，背包完整性保持未确认。

网站分享码使用位置编码。适配器先用该网站自己的符文排列解码为名称，再按名称映射本地补丁 ID；不直接套用本地符文排列。名称缺失、布局不支持或装备不属于召唤师峡谷时明确报错或阻止对应应用。网站与录像版本不同可以选取仍存在的同名条目，但所有数值都读取本地补丁资料。

首次解析时获取网站公开的 page-data，保存精简排列、版本和来源哈希，以便离线复核；不会复制网站应用程序、插入脚本或自动操作游戏客户端。此网站当前没有经本项目确认的直接回传 API，不能将“网页已打开”理解为配置已导入。其接口变化或下线后，可改用内置选择器。

## 7. 其他选择器的回传接口

提供给外部网站维护者的适配器为 [selector_bridge.js](../integrations/selector_bridge.js)。可在其自己的选择器页面中引用；不需要访问用户的录像、截图、标注或本地服务令牌。

```js
import { connectWorkbench } from './selector_bridge.js';

const bridge = connectWorkbench({
  projectUrl: 'https://your-selector.example/',
  updatedAt: '2026-10-16',
  onConfiguration(configuration) {
    // Use your own UI to display and edit the selected IDs.
  }
});

// After the user clicks your submit button:
// bridge.submit(configuration);
```

在工作台的“外部选择器回传 / 配置导入导出”输入该网页 HTTPS 地址并打开。工作台发送独立随机 nonce 和回传 origin；网页使用 postMessage 返回选择。校验发送窗口、精确 origin、nonce、声明的 2026 年或以后更新时间及精确补丁，再让用户确认导入。更新时间是提供者声明，不是对第三方代码的审计认证。

通信格式：

```json
{
  "type": "lol-workbench.selector.result",
  "nonce": "the-per-launch-bridge-nonce",
  "provider": {
    "project_url": "https://your-selector.example/",
    "updated_at": "2026-10-16",
    "data_patch": "16.6.1"
  },
  "configuration": {
    "schema_version": 1,
    "match_setup": {
      "patch": "16.6.1",
      "sides": {
        "blue": {"champion": null, "rune_page": {}},
        "red": {"champion": null, "rune_page": {}}
      }
    },
    "snapshots": []
  }
}
```

这是一份空白结构，实际回传应保留原配置中的英雄并填入对应 ID；缺少的符文位置可为 null。完整配置也可通过导出、文件导入转移到其他工作区。回传只保存选择，不能将 verified 或网页显示的数值当成已核验游戏机制。

普通网页只有在实现这一接口后才能直接回传；浏览器的跨站限制不允许工作台读取任意模拟器内部的选择。其他可解析分享格式可另写身份适配器。名字、ID 和文件导入都不要求接入一个完整的战斗模拟器。

## 8. 后台资料、导出与机制边界

配置保存在 project.json 的 configuration 中。catalogs/ 保留锁定的目录与所选英雄技能资料。普通评估包增加：

- assessment/configuration.json：固定配置和快照索引。
- assessment/hero_data.json：片段开始时可取得的配置与原始资料。
- assessment/hero_states.json：每个已记录时点的双边配置资料。
- catalogs/：离线重读所需目录、英雄资料及存在时的外部选择器排列证据。

短时任务草稿携带介入时刻可见的固定配置、最近快照和英雄资料，不带未来快照。等级、技能加点、装备和符文 ID 已进入后台；推演单位参数仍要求经过核验，静态引用不会自动将 rules.verified 设置为 true。

资料中包含普通基础属性成长参考、所选技能等级对应的射程/冷却/消耗原值，以及被动、符文与装备描述。基础属性成长参考不包含英雄特例，攻速成长加成与基础攻速分列，不假设攻击速度比率；技能原值也不保证已经体现急速、形态或其他条件修正。未解析的技能占位符、特殊前摇和条件效果保持待核验。

calculation_status 为 selection_and_static_references_only，verified_effective_state 保持 false。选择成功与完整战斗机制已实现是两个独立状态。已有高级 JSON 输入可继续用于独立的人工/AI 规则适配，但不会覆盖版本锁定配置的来源记录。
