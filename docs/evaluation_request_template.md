# 短时补兵决策评估任务

请使用随包框架，以双方各自的决策时刻可见信息为依据，分别评估双方。不要使用玩家身份或已知段位作为评分条件，不要把事后结果当作当时必然可知的信息。

1. 先核对 project.json、annotations.json、tables/coverage.json 和截图。空白代表未知或不适用，不代表零；reviewed=false 的坐标未经复核。先报告阻碍计算的缺失项。核验双方英雄版本、等级、技能加点、符文、装备、实际攻速、移速、射程与状态；资料不足时给条件性结论，不制造精确分数。
2. 按双方分别列出决策点、合法候选行为、所用参数、公式代入和不确定区间。区分小兵死亡时间与英雄可以支配的时间。动作开始间隔采用 actions.csv，不得把截图采样间隔视为攻击间隔。
3. 只使用 distances.csv 中明确的两个单位 ID、阵营及对应截图，考察英雄间距离以及各英雄到对方存活小兵的距离。游戏单位距离只是用户标尺下的估计，不能直接当作精确射程边界。
4. 先评估策略是否符合当时的条件，再评估资源、成本、位置调整、攻击相位、被动与符文机会利用。使用框架中的固定配置，列明权重、归一化规则、缺失项处理和评分区间。若没有可重复执行的评分配置，不得自行填写任意权重并宣称客观总分。
5. 对已完成片段分别评分；多个片段比较时统一时间窗口、英雄阶段、配置与可观察条件。对未完成片段从最后可确认状态构造未来短时事件链，明确敌方反应假设和机制参数来源。反事实分支保持同一初态，并展示资源和状态成本差异。
6. 输出 evidence（证据）、assumptions（假设）、parameters（参数）、calculations（计算）、per_player_results（双边结果）、uncertainty（不确定性）。保留表格行号、frame_id、时间与截图引用，使他人可核验。建议将报告保存在 assessment/result.md，将使用的评分配置保存在 assessment/scoring_config.json。

可选：完成评估后，将少量候选动作及双方回应转成收益矩阵，写明收益单位、权重、assessment_reference 和 game_type。只有可合理视为两人零和的矩阵才可交给主程序 solve；求解只对这个有限矩阵成立。
